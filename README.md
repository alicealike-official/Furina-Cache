# Furina-Cache

## 项目介绍

Furina-Cache 是一个用于学习 Cache 架构和 IC 开发流程的实践项目，涵盖架构分析、RTL 设计、UVM 验证、参考模型，以及后续的性能、功耗和面积评估。

项目目前不面向具体系统集成或工程应用，也不以工程交付为目标。部分设计选择、文档和评估方法可能还不够严谨，会随着学习、验证和实现结果持续修订。

仓库保留两个版本：**v1.0 已完成，v2.0 正在开发和验证。**

## 版本演进

### Cache v1.0：基础架构与 UVM 实践，已完成

v1.0 使用 Verilog 实现简单的阻塞式 Cache，并搭建配套 UVM 验证环境，主要用于熟悉 Cache 的基本工作过程，以及激励、驱动、监视和结果检查等验证方法。

这一版本没有进行深入的微架构优化，也没有设定 PPA 或验证覆盖率的验收要求。**v1.0 已按其学习和实践范围完成**，保留设计与验证代码供阅读、比较和复用；它不代表经过完整覆盖率闭合或工程签核的 Cache IP。

设计位于 [Design/Cache](Design/Cache)，验证环境位于 [verif_env](verif_env)，架构说明见 [v1.0 技术文档](Architecture/Cache_Technical_Report.md)。

### Cache v2.0：重新设计的非阻塞 DCache，开发中

v2.0 从架构和实现上重新组织，采用 SpinalHDL 进行参数化设计，围绕 MSHR、WBB、流水控制及响应通路构建非阻塞 DCache，同时建立模块 IP 与顶层集成分层的验证体系。

这一版本希望进一步学习并发事务、跨周期数据依赖、资源管理和标准总线接入，并把 PPA 目标与验证覆盖率要求纳入开发过程。

## v2.0 的主要特性与设计动机

下表包含已实现的设计内容和版本目标；具体完成程度见后文的进度表。

| 特性 | 引入原因 |
| --- | --- |
| 两级流水与 Stage2 冻结 | 划分处理阶段、控制组合路径长度，并处理接收请求后资源状态发生变化的情况 |
| MSHR 与同行请求合并 | 跟踪多个未完成请求，将同一缓存行的访问合并，减少重复内存读，并支持未命中期间处理其他访问 |
| WBB 与槽位预留 | 在后台写回脏行；淘汰前先确保有位置保存数据，避免部分淘汰导致数据丢失 |
| Way Lock | 保护正在填充、重放的路，避免被再次分配、替换或错误命中 |
| 独立读写响应队列 | 保存命中与重放结果，处理 CPU 反压及不同响应来源的竞争 |
| FIFO、LRU、PLRU 替换策略 | 学习不同策略的行为、状态维护及与锁定资源配合时的取舍 |
| 顶层 AXI 接口 | 学习标准总线接入、并发事务、ID 管理和反压处理，属于 v2.0 的目标范围 |
| IP 与顶层分层验证 | 分别检查模块接口契约和实际连接，便于定位问题、安排场景及管理覆盖闭合 |
| C++ 参考模型与稀疏内存 | 提供数据和行为检查依据，并支持可控的内存响应延迟、背压及事务顺序 |

## v2.0 的 PPA 与验证目标

### PPA 目标

| 维度 | 目标或当前口径 |
| --- | --- |
| 工艺 | TSMC 28 nm |
| 时钟频率 | **目标 700 MHz**；目前不作为已达成的实现结果 |
| 面积 | 待定，参考可比设计或产品资料，并结合本项目配置确定 |
| 功耗 | 待定，结合可比对象、工作负载和评估条件确定 |

后续 PPA 结果需要同时说明工艺库、PVT 条件、Cache 容量与配置、存储体实现，以及评估处于综合还是布局布线阶段。面积和功耗参考值应在可比条件下使用，具体预算尚未确定。

### 验证与覆盖率要求

v2.0 将验证点闭合与覆盖率作为开发要求，包含功能覆盖率、代码覆盖率和断言检查。具体目标数值、有效覆盖项、排除项及验收标准仍需细化，当前不填写尚未确定的百分比。

- **功能验证**：以验证点为依据组织 case，检查数据、时序、资源边界和并发组合，并保存场景实际命中的证据。
- **代码覆盖率**：用于发现未执行的逻辑和遗漏场景，结合功能需求审查，不单凭测试数量判断充分性。
- **断言与环境自检**：检查接口协议和关键不变量，确认检查器能识别错误，并避免断言因前提未发生而空通过。
- **分层闭合**：WBB、MSHR 的 IP 验证和 DCache 顶层集成验证分别登记；基础 smoke 或模块回归通过不自动代表整个 v2.0 完成。

验证点及 case 规划见 [DCache v2.0 验证计划](验证计划/DCacheWithMshr)。
