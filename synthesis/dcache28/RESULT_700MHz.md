## 哪条路径不满足

最差路径：

```text
s1Index[3]
    ↓
29级组合单元（包括8级缓冲）
    ↓
UnitCache.rdValidPipe_0
```

这是组索引寄存器到CacheMem读取有效位寄存器的路径；两端都是寄存器，不是某个外部IO预算过紧。映射实例分别为`_1381930_`与`_1344950_`，可在原始SS报告与网表中直接定位。

| 最差路径组成 | 延迟 |
| --- | ---: |
| 发起触发器clock-to-Q | 0.0928ns |
| 组合传播（根据到达时间相减） | 约1.3764ns |
| 其中8级buffer的报告增量合计 | 约0.2901ns |
| 数据到达 | 1.4692ns |
| 周期 | 1.428571429ns |
| 扣除时钟不确定度 | 0.0500ns |
| 扣除捕获触发器setup | 约0.0217ns |
| 允许到达 | 1.3569ns |
| 裕量 | −0.1123ns |

单元增量按4位小数打印，逐项求和可能有0.1ps级舍入差。此处CKBD单元作为数据/控制路径buffer使用，不代表已经建立实际时钟树。

前10条最差路径全部从`s1Index[3]`出发，并集中到CacheMem读状态。部分端点如下：

| SS端点 | 裕量 |
| --- | ---: |
| UnitCache.rdValidPipe_0 | −112.3ps |
| UnitCache.banks_2_14_rd1RecA | −110.2ps |
| UnitCache.rdValidPipe_2 | −105.7ps |
| UnitCache.banks_3_9_rd1RecA | −103.6ps |
| UnitCache.banks_1_2_rd1RecA | −98.0ps |

因此优化应优先聚焦组索引到CacheMem读状态更新的组合链及其缓冲传播。不能只更换最慢的一个门就认定能解决：最慢单门约87ps，整条路径仍有较多级。是否需要预解码、控制信号局部化、改变存储结构或增加流水，需要下一步结合架构权衡，本轮没有实施。

在保持本轮网表与其它约束不变、仍无布线寄生时，按负裕量估算的临界周期约1.5409ns，对应约649MHz。这个数不是布局布线后的最高频率，也不是全PVT签核结果。

## 约束和可信范围

- ABC以SS库优化，组合延迟目标取整数1428ps；输入驱动BUFFD1BWP40P140，输出负载10fF。最终setup结论由OpenSTA独立给出，不能用ABC显示的组合延迟代替完整寄存器时序检查。
- 时钟不确定度50ps、时钟转换时间50ps；输入/输出延迟各200ps，输入转换时间50ps、输出负载0.01pF。这些是评估假设，沿用前一轮口径，不冒充系统接口规格。
- 597位普通输入和633位输出均已约束；resetn单独处理并排除其时序路径。时钟ideal，无布线寄生、布局、CTS或提取RC。
- OpenSTA的18个未约束端点逐项核对为常量：内存地址低6位、内存ID高2位及固定ready。没有未解释的普通未约束端点；两角均未出现其它STA warning或error。
- 综合前仍为262个数组、265,000bit，包含物理副本；所有存储均映射为标准单元。面积和关键路径不能直接代表SRAM宏实现，也不代表物理核心面积。若后续接入SRAM或改1R1W加仲裁，必须重新综合和分析。
- 未做活动驱动功耗、门级形式等价、hold、复位recovery/removal或全PVT签核。
